# 看板合并冲突的唯一口径（2026-11-08）

- 对应看板行：`MERGE-1`
- 机器判据：`scripts/gate/kanban_merge_policy.py`，由**既有工具** `scripts/gate/kanban_render.py check` 调用
- 门禁分母：**168 不动**（没有新增 `check_*`，没有进 `STAGE_CONFIG`）

## 1. 口径（唯一，不再按侧丢文本）

合并冲突时**两侧的证据都要留**。每条线补充内容时用**带身份前缀的 marker** 标注，便于机器识别：

| 线 | marker 形态 |
|---|---|
| 本线（omp-macmini） | `〔omp-macmini 线补记 ……〕` |
| 对方（mcode-macmini） | `〔mcode-macmini 线补记 ……〕` |

若某个 PR **有意**删掉某一侧的行文本，必须在该行里**显式声明**：

```
〔删去另一侧：<原因>〕
```

没有声明 ⇒ 机器判据判红。

## 2. 机器判据（三条）

1. **单侧 marker 的行**：必须 (a) 属于历史遗留清单，或 (b) 带显式删除声明；否则判红。
2. **全表两侧 marker 的总计数都必须非 0** —— 任一侧被整体丢掉 ⇒ 判红（这正是 2026-11-06 那次合并的形态）。
3. 历史遗留清单里的行**允许已被补齐**（补齐后不必从清单里删）。

## 3. 历史遗留清单（逐个列名，不做静默豁免）

2026-11-06 的 develop 合并**按侧丢文本**：本线在 13 行里写的「合并保留两侧证据（未自行裁定）」标记**一处都没留下**，
对方的 13 处却都留着 ⇒ 谁留谁丢没有唯一口径（这正是本行立的原因）。

2026-11-08 实测当前板子：**11 行只有一侧 marker** ——

- 只有本线：`HO-1`、`IL-4`、`LB-1`、`P1-5`、`P2-2`、`DEBT-2`
- 只有对方：`BIN-1`、`ENG-11`、`ENG-12`、`EX-10`、`WIRE-1`

⇒ 这 11 行进入 `kanban_merge_policy.GRANDFATHERED`（逐个列名）。
**下一个触及这些行的 PR 必须补齐另一侧文本，或写明删除声明** ⇒ 否则判据判红。
清单里的行若日后被补齐，判据仍允许它留在清单上（判据只看「有没有单侧且没声明」）。

## 4. 自检（反向变异，5 个臂）

`python3 scripts/gate/kanban_merge_policy.py --selftest`：

| 臂 | 构造 | 期望 |
|---|---|---|
| A | 单侧 marker 且不在历史清单 | 判红 |
| B | 单侧 + `〔删去另一侧：…〕` 声明 | 不判红 |
| C | 两侧都有 | 不判红 |
| D | 历史清单里的单侧行 | 不判红 |
| E | 某侧 marker 全部消失 | 判红（聚合判据） |

端到端反向变异（实测，2026-11-08）：往板子里插一行只有本线 marker 的合成行 ⇒
`kanban_render.py check` ⇒ **rc=1**，输出
`merge policy: row ZZ-PROBE 只保留了本线的合并补记，另一侧的行文本不见了；要么补齐另一侧，要么在该行写明 〔删去另一侧：<原因>〕`。
