## 1. 口径教训（SF-08 家族）—— 本工具存在的理由

整改方案 §P2-1 的原话：

> 生成物「写盘口径」必须等于「核对口径」。把墙钟时间放进 H1 标题或索引字段
> ⇒ 逐字节比对必然永远红。sqlrustgo 门禁输出里的 `Date: $(date -u ...)` 同理，
> 需从复现比对域剔除。

所以本工具**从设计上**堵死了这条：

| 做法 | 为什么 |
|---|---|
| 索引里**没有任何时间戳** | 有时间戳 ⇒ 每次重生成都不同 ⇒ 逐字节比对永远红 ⇒ 判据变摆设 |
| 文档版本用**内容哈希**表示，且哈希**排除 stamp 行本身** | 否则「写 stamp 会改变哈希」⇒ 自指 ⇒ 永远红 |
| 「新鲜度」判 **stamp 与内容是否一致**，不判「距今多久」 | 「距今多久」是墙钟，属于展示域，不属于复现比对域 |
| 索引里带 `updated_at` 这类字段名 ⇒ 直接判红 | `updated_at` 是墙钟的典型形状 |

scripts/gate/xxx.sh 本来就是占位符）。

按该门禁**自己的书写约定**修（不是登记进基线压掉）：

> A document that quotes a path known to be broken must write it as plain prose —
> otherwise the document that documents a broken pointer **becomes** a broken pointer.

⇒ 把这 5 处从反引号路径改成**普通散文**。修完：

```
pointers in scope: 35 broken, 35 registered as known debt
[OK] no broken pointer outside the recorded debt
[OK] Documentation Pointer-Path Gate
```

**新增悬空路径 0**。存量 35 条仍按既有基线记账（属 IL-5 之外的既有债，本轮不动）。

## 4. 反向变异：五臂

| 臂 | 做法 | 期望 | 实测 |
|---|---|---|---|
| M1 | 改一份文档的内容但不重新 stamp | 判红 | rc=1，`索引与重生成结果不一致` |
| M2 | 往**已提交索引**里塞一个墙钟时间戳 | 判红 | rc=1，索引不一致 |
| M3 | 文档里加一个坏的反引号路径 | 判红 | rc=1，**两条**都红（索引不一致 + 既有指针门禁 exit 1） |
| M4 | 让**生成器**写出墙钟时间（SF-08 的真实失效形态） | 判红 | rc=1，两条墙钟形状被点名 |
| M5 | 生成器恢复但索引里留着墙钟 | 判红 | rc=1，索引不一致 |
| 恢复 | 全部还原 | 判绿 | rc=0，`doc_facts: OK` |

M4 是关键的一臂：它证明**不是**靠「索引不一致」顺带抓到的，
而是墙钟护栏**自己**会红，并且能点名是哪种形状：

```
FAIL: 索引里出现墙钟时间形状 '\\b(19|20)\\d{2}-\\d{2}-\\d{2}T\\d{2}:\\d{2}' —— 墙钟不得进复现比对域
FAIL: 索引里出现墙钟时间形状 '\\bupdated_at\\b' —— 墙钟不得进复现比对域
```

M5 证明另一半：生成器干净了但索引脏了，**仍然**红 ——
「写盘口径 == 核对口径」这条是独立成立的，不是靠护栏顺带。

## 6. 残余风险与未闭环部分

- **存量 35 条坏指针仍在**（既有基线记账）。本轮只保证「不新增」，
  没有逐条修 —— 修它们要改历史 release 文档，那些是**冻结资料**，
  改了会让证据描述一个从未存在过的状态（该门禁头部原话）。
- **`doc_stamp` 没有对全部 86 份文档批量写入**。能力是完整的
  （`stamp --write` 可用、`--file` 可限定范围），但批量写会动 86 份文档，
  且 stamp 行要放在 H1 之前，可能与「文档首行是标题」这类既有约定相撞。
  本轮只在**本报告**上打戳做了端到端验证，其余留给 Owner 决定何时批量铺。
- **索引是 v4.1.0 scope 的**，不是全仓的；全仓口径的文档索引本轮未做。
- **`doc_freshness` 的「距今多久」不进判据**，只作展示（git 提交日期）。
  这意味着「三个月没更新的文档」不会被判红 —— 这是刻意的：
  墙钟不是复现域。
- **本条不构成门禁通过声明**：本仓未跑 `ci_gate.sh`。
  归档 run 侧的第二血统复核仍被 IL-9（CI 执行面，runner-03 缺镜像）挡住。
