# IL-10：A04 证据门禁的假红 —— 「引擎不可用」被当成了「证据漂移」（2026-11-05）

## 0. 结论先行

| | 改动前 | 改动后 |
|---|---|---|

## 1. 根因链

```
tests/common/bin_resolver.rs 的 PATH 回退
  → 取到 /Users/liying/.cargo/bin/sqlrustgo（2026-02-21 的全局安装）
    → 它不支持 `sqlite --batch --mode csv --headers true --cmd`
      → 照旧打印 REPL 横幅，然后**以 0 退出**
        → 生成器把它当 CSV 解析，产出「假证据」
          → 门禁拿假证据跟归档证据比 ⇒ 20 处 MISMATCH
            → 归因「归档证据已与引擎漂移」
              → 立 #5466（priority/p0）
```

链底那一环（**生成器把不可用产出当成可比结果**）今天仍在；
链上第二环（**门禁比对域含残留文件**）也是今天才发现的。

### 判定口径的不对称

实测确认（`tests/integration/compat/a04_mysql_diff_matrix_test.rs:1433`）：

| 引擎状态 | 生成器怎么判 | 门禁怎么说 |
|---|---|---|
| 引擎**不存在**（postgres 参考容器起不来） | `EngineResult::unavailable` ⇒ **不写文件** | NOT VERIFIED ⇒ NOT RUN 披露 |
| 引擎**存在但干不了活**（陈旧二进制，只出横幅） | `parse_cli_csv` 照收 ⇒ **写文件** | 拿假文件去比 ⇒ **MISMATCH ⇒ 判红** |

同一类问题（引擎不可用），两种完全相反的处理。
「引擎不可用」必须一律落 NOT RUN，不能因为「二进制跑起来了、退出码是 0」就算数。

## 2. 修法

### 2.1 生成器（`tests/integration/compat/a04_mysql_diff_matrix_test.rs`）

`run_sqlrustgo_cli` 在解析 CSV **之前**先判「这个二进制到底进没进 sqlite 批处理模式」：

```rust
if looks_like_repl_transcript(&stdout) {
    return EngineResult::unavailable(
        "sqlrustgo_cli",
        &format!(
            "binary at {} does not support the `sqlite --batch --mode csv \
             --headers true --cmd` interface (it fell through to the REPL); \
             point {} at a current build \
             (cargo build -p sqlrustgo-cli --bin sqlrustgo)",
            bin,
            bin_resolver::ENGINE_BIN_ENV
        ),
    );
}
```

判据 `looks_like_repl_transcript` 看 stdout 里有没有 REPL 的形状
（`SQLRustGo Database System initialized` / `sqlrustgo>` /
`Type 'exit' or 'quit' to exit.` / `Goodbye!`）。

**为什么不是「看退出码」**：陈旧二进制是**以 0 退出**的
（它打印完横幅和 `Goodbye!` 就正常结束）。退出码 0 在这里**不**意味着查询成功。
⇒ 判据必须看**输出形状**，不能看退出码。

**为什么不给 `bin_resolver` 加能力探测**：resolver 被全仓多处使用，
把「某个 CLI 支持某个子命令」塞进通用定位器会让它承担不属于它的语义。
判据放在**调用点**（谁在驱动这个接口，谁负责判接口可用性）更贴合职责边界。

自带两个单元测试（判据自证）：真 CSV 输出不得误判；真 REPL 输出必须判出来。

### 2.2 门禁（`scripts/gate/check_a04_evidence_reproducible.sh`）

```bash
rm -rf "$FRESH"
if ! cargo test --test a04_mysql_diff_matrix ...
```

**比对域必须只含本次产出。** 目录里可能留着上一次运行的文件：
某个引擎这次不可用 ⇒ 生成器不写文件 ⇒ 但旧文件还在 ⇒
门禁照样拿它去比，把「这次没产出」误判成「产出了且一致」。

⇒ 这一条同时堵住**假绿**（拿旧文件冒充本次产出）与**假红**。

## 3. 反向变异（验收口径逐条对照）

验收口径原文：
> 反向变异：换上 2026-02-21 的陈旧全局 sqlrustgo，门禁必须转 NOT RUN 披露、
> 且不得再报「证据漂移」。

| 臂 | 做法 | 期望 | 实测 |
|---|---|---|---|
| A | `SQLRUSTGO_BIN=/Users/liying/.cargo/bin/sqlrustgo`（2026-02-21） | 转 NOT RUN 披露，不报漂移 | rc=0；`STATUS: NOT RUN for 40 archived file(s)`（20 postgres + 20 sqlrustgo_cli）；**MISMATCH 0 条，「drifted」0 次** |
| B | 正常（当前构建） | 仍 80/80 逐字节一致 | rc=0；门禁输出「80/80 comparable archived evidence file(s) match this run byte-for-byte」；NOT VERIFIED 20（仅 postgres） |
| C | 生成器产出的文件数（陈旧二进制下） | sqlrustgo_cli 不产文件 | `ls target/a04-5226/wire/ \| grep -c sqlrustgo_cli` = **0**；另三个引擎各 20 |

臂 A 的 40 条 NOT VERIFIED 正是**应该**的样子：
20 条是 postgres 参考容器不可用，20 条是「陈旧二进制 ⇒ 该引擎不可用」。
改动前这 20 条是被当成「证据漂移」的假红。

## 4. 这条为什么重要

#5466 是 **priority/p0**，它的成立完全依赖「归档证据与引擎漂移」这个归因。
本轮实测：**归档证据没漂移** —— 80/80 逐字节一致。
那条 P0 债是**一次假红造出来的**。

假红比假绿危险的地方在于：假绿会被人发现，假红**看起来像真问题**，
于是有人去「修」它 —— #5466 的评论里就写着「复核后两条核心论断不成立」，
但结论已经进了 issue 列表、进了优先级、进了工时估算。

**这次修的正是「假红的制造机」**：不是把这一次的红压掉，
而是让「引擎不可用」这件事从此只能以 NOT RUN 的形状出现。

## 6. 残余风险与未闭环部分

- **门禁脚本被改动**（🟡）。改前漏什么：门禁把「引擎不可用」当成「证据漂移」，
  制造假红；改后多报什么：**不多报任何一条红** ——
  不可用时转成 NOT RUN 披露（NOT RUN ≠ 通过，门禁自己明说）。
- **`bin_resolver` 的 PATH 回退本身没改**。它仍然可能取到陈旧二进制 ——
  本轮是让**调用方**判出「这个二进制不支持我驱动的接口」。
  通用定位器要做能力探测，属于另一个话题。
- **判据是形状匹配，不是协议级校验**。若某个二进制输出 CSV 但列名/语义不对，
  仍会被当成可比结果 ⇒ 那属于「引擎真的干了活但干错了」，归 MISMATCH 是对的。
- **本条不构成门禁通过声明**：本仓未跑 `ci_gate.sh`。
  归档 run 侧的第二血统复核仍被 IL-9（CI 执行面，runner-03 缺镜像）挡住。
- `#5466` 本身的关闭仍待 Owner 裁定（见 IL-3 报告）。
