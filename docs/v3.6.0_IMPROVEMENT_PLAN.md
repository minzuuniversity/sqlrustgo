### 测试文件分析

**window_function_test.rs** (解析测试)
- 覆盖 LEAD, LAG, FIRST_VALUE, LAST_VALUE, NTILE, NTH_VALUE
- 测试解析器对窗口函数的支持
- 包含 ORDER BY / PARTITION BY 组合

**window_function_execution_test.rs** (执行测试)
- 使用真实 ExecutionEngine 测试
- setup_sales_data 辅助函数
- ⚠️ 仅验证 `!result.rows.is_empty()` - 断言较弱

**window_function_boundary_test.rs** (边界测试)
- Issue #878 驱动
- NTILE: partition, bucket > rows, null handling
- LEAD/LAG: offset, default value, large offset
- FIRST_VALUE/LAST_VALUE: order by dependency, partition, default frame
- NTH_VALUE: out of range, from last row

## 改进方案

### P0 - 高优先级

#### 1. 强化测试断言

**文件**: `tests/window_function_execution_test.rs`

**问题**: 当前断言过弱，无法验证正确性
```rust
// 当前 (弱断言)
assert!(!result.rows.is_empty());

// 改进 (强断言)
let values: Vec<i64> = result.rows.iter()
    .filter_map(|row| row.get("LEAD(amount)").and_then(|v| v.as_integer()))
    .collect();
assert_eq!(values, vec![150, 120, 180, NULL]);
```

**工作量**: 1d

#### 2. 补充 parser 未覆盖分支测试

**目标**: parser/mod.rs 覆盖率从 78.74% 提升至 85%

**关键未覆盖路径**:
- 复杂表达式解析边界情况
- 错误恢复路径

**工作量**: 2d

### P1 - 中优先级

#### 3. 添加快照测试框架

**工具**: insta crate

**用途**: 验证窗口函数输出一致性，防止意外变更

**工作量**: 1d

#### 4. Docusaurus 文档配置

**建议目录结构**:
```
docs/
├── docusaurus.config.js    # Docusaurus 配置
├── docs/                    # 版本化文档
│   ├── intro.md
```

**功能**:
- MDX 支持 (可交互示例)
- 版本化文档
- Algolia DocSearch 集成

**工作量**: 3d

### P2 - 低优先级

#### 5. 性能回归测试

**目标**: 确保窗口函数性能不退化

**工作量**: 2d

#### 6. Algolia DocSearch 集成

**工作量**: 1d
