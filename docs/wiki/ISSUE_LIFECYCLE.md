# Issue 创建生命周期规范

> **版本**: v1.0
> **日期**: 2026-05-11
> **目的**: 规范化新版本开发周期中 Issue 的创建流程

---

## 一、核心原则

### 1.1 Issue 创建时机

**每个版本必须创建完整的 Issue 体系，包括：**

| Issue 类型 | 创建时机 | 示例 |
|------------|----------|------|
| **总控 Issue** | 版本规划阶段 | v3.1.0 总控 Issue |
| **功能任务 Issue** | 规划评审后 | P0/P1/P2 任务分组 |
| **门禁检查 Issue** | 里程碑定义后 | Alpha/Beta/RC/GA Gate |

### 1.2 主仓库原则

> **重要**: Gitea 是主仓库 (origin)，GitHub 仅作为 release 镜像。

| 仓库 | 用途 | push 权限 |
|------|------|----------|
| **Gitea (origin)** | 开发、Issue、PR | ✅ 允许 |
| GitHub (github) | release 镜像 | ❌ 仅读 |
| Gittee (gitee) | release 镜像 | ❌ 仅读 |
| Gitcode (gitcode) | 备份镜像 | ❌ 仅读 |
| Bitbucket (bitbucket) | 备份镜像 | ❌ 仅读 |

## 二、Issue 创建流程

### 2.1 新版本 Draft 阶段 (必须执行)

```
┌─────────────────────────────────────────────────────────────────┐
│                   新版本 Issue 创建流程                           │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  Step 1: 创建总控 Issue                                         │
│  ─────────────────────────────────────────────────────────────  │
│  - 版本目标与里程碑                                             │
│  - P0/P1/P2 任务概览                                           │
│  - 关联文档链接                                                 │
│  - 资源估算                                                     │
│                                                                  │
│  Step 2: 创建功能任务 Issue                                     │
│  ─────────────────────────────────────────────────────────────  │
│  - P0 阻塞项 Issue (子任务清单)                                 │
│  - P1 重要功能 Issue (子任务清单)                               │
│  - P2 优化项 Issue (如有必要)                                  │
│                                                                  │
│  Step 3: 创建门禁检查 Issue                                     │
│  ─────────────────────────────────────────────────────────────  │
│  - Alpha Gate Issue (目标日期 + 检查清单)                       │
│  - Beta Gate Issue (目标日期 + 检查清单)                        │
│  - RC Gate Issue (目标日期 + 检查清单)                          │
│  - GA Gate Issue (目标日期 + 检查清单)                          │
│                                                                  │
│  Step 4: 关联 Issue                                             │
│  ─────────────────────────────────────────────────────────────  │
│  - 在总控 Issue 中引用子任务 Issue                              │
│  - 在各子任务 Issue 中引用总控 Issue                            │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 Gitea Issue 创建 (主仓库)

```bash
# 使用 Gitea API 创建 Issue
AUTH="openclaw:<token>"

# 创建 Issue
curl -s -X POST "http://192.168.0.252:3000/api/v1/repos/openclaw/sqlrustgo/issues" \
  -u "$AUTH" \
  -H "Content-Type: application/json" \
  -d '{
    "title": "Issue 标题",
    "body": "Issue 内容 (支持 Markdown)"
  }'
```

### 2.3 GitHub Issue 仅用于 release 发布同步

> **注意**: GitHub Issue 不应作为开发主追踪工具。

## 四、Issue 关闭规则

> **参考**: [ISSUE_CLOSING_VERIFICATION.md](./ISSUE_CLOSING_VERIFICATION.md)

### 4.1 禁止的行为

| 禁止行为 | 原因 |
|-----------|------|
| 手动关闭无 PR 的功能 Issue | 无法追踪实际完成状态 |
| 批量关闭多个 Issue | 每个 Issue 需要独立验证 |
| 关闭追踪 Issue 但不验证子任务 | 任务状态不一致 |

### 4.2 Issue 关闭检查清单

关闭 Issue 前必须确认：

```bash
# 1. 检查 Issue 是否已关联 PR
gh issue view <id> --json closedByPullRequestsReferences

# 如果为空，说明没有 PR 关闭该 Issue，不能手动关闭！
```

## 五、版本阶段与 Issue 状态

| 阶段 | Issue 状态 | 说明 |
|------|------------|------|
| Draft | 🟡 规划中 | Issue 已创建，尚未开始开发 |
| Active | 🟢 开发中 | 正在实现相关功能 |
| Blocking | 🔴 阻塞 | 遇到阻塞问题需要升级 |
| Done | ✅ 完成 | 相关功能已实现并通过验收 |
| Closed | ❌ 关闭 | 版本发布后，Issue 归档 |
