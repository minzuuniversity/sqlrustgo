# DeepSeek 实施计划：移动优先 AI 驱动 GMP 系统

> 来源：DeepSeek 对话
> 日期：2026-05-20
> 状态：实施计划

---

## 一、设计原则

1. **最小化录入（Zero-Input Goal）**：现场操作人员不再填写大量表单，而是用拍照、语音、短视频等最自然的方式记录。
2. **Agent 原生（Agent-Native）**：HermesAgent 是所有非结构化数据的"第一接收者"，负责理解、结构化、关联、验证。
3. **GMP 规则驱动流（Compliance-Driven Workflow）**：Agent 整理出事实数据后，GMP 规则自动决定下一步流程（如偏差启动、复核通知、放行条件检查）。
4. **可信优先（Trust First）**：所有关键动作和形成的记录，实时写入 SQLRustGo 的不可变审计链，确保原始证据自采集起就具备合规性。
5. **终端极简（Ultra-Thin Client）**：移动端只是一个"多模态采集器 + 通知器"，没有复杂的业务逻辑。

## 二、用户角色与典型场景

| 角色 | 场景 | 输入方式 | Agent 任务 |
|------|------|----------|-------------|
| **操作工** | 仓库收货 / 投料 / 取样 / 清场 | 拍照（物料标签、设备状态）、语音："领了A物料50kg，批号230501" | 识别图片中的文字、批号；语音转文字并提取数量、批号；自动生成物料使用记录；检查是否与工单匹配。 |
| **QA/QC** | 过程控制 / 实验室检验 | 拍照（仪器屏幕读数）、语音："pH=6.8，温度37.2℃" | 提取数值，自动生成检验记录，实时比对标准范围，若超限则立即触发偏差工作流。 |
| **维修工** | 设备故障报修 | 拍短视频展示故障现象，语音说明："3号灌装机，速度下降，异响。" | 提取设备编号、故障描述，自动创建维护工单，并关联设备校准状态。 |
| **生产主管** | 批记录复核 / 放行 | 审批操作可通过移动端语音："审核通过，同意放行"，并辅以人脸/指纹验证。 | 将语音审批转化为电子签名，验证双人复核规则，固化放行证据。 |

## 三、功能需求分析（按 GMP 模块重新划分）

系统核心模块从"管理菜单"转变为"Agent 技能（Capability）"。

### 1. 通用核心能力

- **多模态记录生成（Record-from-Media）**：拍照/视频/语音 → Agent 提取关键信息 → 生成结构化原始记录（如称量记录、清洁记录、环境监测记录）。
- **合规实时检查（Live Compliance Check）**：每条新记录生成时，Agent 即时匹配 SOP/GMP 规则，自动标注"合规/不合规/需人工确认"。
- **流程自动推动（Auto-Workflow）**：记录生成后，Agent 判断是否触发下一步（如需要复核、产生偏差、通知QA），并将待办推送到指定角色。
- **上下文感知补充（Contextual Gap-Fill）**：如果 Agent 发现信息缺失（如照片模糊、缺少批号），会主动反问用户，引导补充关键数据。

### 2. WMS（仓储管理）—— 基于 Agent 的物料跟踪

- 入库：拍照物料标签 + 语音："收到原料A，供应商XX，批号230501"，Agent 完成入库记录并触发取样/检验任务。
- 出库：语音："发往车间1线，工单WO-001"，Agent 自动计算用量、扣减库存、关联工单。
- 盘点：拍照货位全景，Agent 识别物料数量和批号，与系统账目比对。

### 3. MES（生产执行）—— Agent 驱动的电子批记录（EBR）

- 生产前检查：拍照设备状态 + 清场状态，Agent 与生产指令比对，确认环境合格后才能开始。
- 关键工艺参数（CPP）采集：操作工拍下设备仪表盘或HMI屏幕，Agent 读取数值并记录为批记录的一部分，实时进行SPC（统计过程控制）判定。
- 偏差自动生成：任何超限值瞬间触发偏差流程，Agent 生成初步偏差描述，并要求现场确认。

### 4. QMS（质量管理系统）—— 合规闭环

- **偏差管理**：由 MES 或 LIMS 的异常自动触发，Agent 协助分析根本原因（基于RAG检索历史案例和SOP），草拟CAPA。
- **变更控制**：提交变更申请时，拍照旧流程/新设备，语音描述变更内容，Agent 自动进行影响评估（关联哪些SOP、设备、批记录需更新）。
- **CAPA跟踪**：Agent 监控 CAPA 有效性检查日期，提醒收集证据，自动生成效果评估报告。

### 5. LIMS（实验室管理）—— 样本驱动的自动化

- 样本登录：扫描/拍照样本标签，Agent 匹配检验计划并生成待检任务。
- 结果录入：拍照仪器屏幕或检验记录本，Agent 提取数据、自动计算、判断合不合格。
- 趋势分析：Agent 按产品/方法自动生成稳定性趋势图，预警潜在OOS（超标）趋势。

## 五、为什么必须从 GMP 文档和规范开始？

系统的"行为"不再由代码定义，而是由 GMP 知识定义。

- 操作工说"pH 6.8"，Agent 必须知道这个值是否在 SOP 范围内。
- QA 拍照的仪器屏幕，Agent 必须知道要提取哪些参数，并判断是否为 CPP（关键工艺参数）。
- 一个偏差记录生成后，Agent 要自动决定是否需要启动 CAPA，以及由谁处理。

这些知识不是靠代码硬编码的，而是从 GMP 文档中抽取并结构化的。

**因此，第一步必然是：让 HermesAgent 具备 GMP 领域的认知能力。**

---

## 六、现有资产与切入思路

已有起点：基于 HermesAgent 和 GMP 规范文件（约2000个文档）+ QMS 系统的 GMP 合规性检索系统雏形。

文档已经向量化、可检索（RAG）。但仅仅"检索到条款"对于自动执行是不够的，需要从这些文档中提取出可执行的规则。

## 七、实施步骤

### 第一步：GMP 知识建模（2 周）

把非结构化的 PDF/Word 规范，转化为结构化知识。核心产出是三类知识图谱/规则库：

| 知识类型 | 例子 | 用途 |
|----------|------|------|
| **概念与实体** | 物料、设备、批次、SOP、偏差、CAPA、清洁验证、CPP、CQA…… | 让 Agent 听懂操作工在说什么。 |
| **流程模型** | 生产指令执行流程：清场确认 → 投料 → 混合 → 取样 → 检验 → 放行 | 让 Agent 知道"下一步该做什么"，推动工作流。 |
| **判定规则** | 混合时间必须在 20±2 分钟；压片机压力范围；双人复核要求；偏差分级标准 | 让 Agent 自动判断合规性，触发偏差或审批。 |

**具体执行方法：**

1. **梳理 2000 个文档**，按类型分类：
   - 法规（GMP 正文、附录、ICH 指南）→ 提取抽象规则
   - 企业 SOP → 提取具体可执行标准
   - 批记录模板 → 提取数据采集节点和参数要求
   - 验证文件 → 提取设备/方法/清洗验证可接受标准

2. **使用 HermesAgent 辅助提取**：
   - 利用 RAG 能力，问 Agent："从 SOP-xxx 中提取所有关键工艺参数及控制范围。"
   - Agent 返回表格后，人工审核，存入规则库。

3. **建立规则库**（YAML / DSL 形式）：

```yaml
rule_id: PRD-001
description: 混合时间控制
applies_to: 工序-混合
parameter: 混合时间/min
acceptable_range: [18, 22]
sop_ref: SOP-MFG-101 v3.2
violation: deviation
severity: major
```

4. **建立实体关联**：
   - 产品 → 工艺规程 → 工序 → SOP → 参数控制列表
   - 设备 → 校准计划 → 使用日志
   - 人员 → 培训记录 → 授权操作范围

这样，Agent 就不再是"查文档的助手"，而是可以推理的合规大脑。

---

### 第二步：选择最小可行场景，落地验证（4 周）

完成知识建模后，不要立即铺开所有模块。选择一个最经典的 GMP 操作，从头到尾跑通。

#### 推荐场景：**"称量操作"**

**原因**：
- 几乎所有药品生产都涉及，是 WMS/MES 的交汇点。
- 操作简单，但合规要求高：物料确认、称量范围、双人复核、设备校准状态、清洁状态。
- 能充分验证"移动端采集 → Agent 理解 → 规则判定 → 审计固证"的完整链路。

**流程设计**：

1. 操作工微信小程序选择任务："XX产品 投料称量"。
2. Agent 从知识库中得知该工序需要的物料、标准称量量、允差、所需设备、人员资格。
3. 操作工拍照物料标签 → Agent OCR 提取批号和物料名，验证是否与工单一致。
4. 操作工语音："称取 A 物料 50.2 kg" → Agent 提取数值，比对标准范围。
5. 自动验证：该人员是否培训过？该天平是否在有效期？前次清场是否通过？
6. 若一切通过，Agent 生成完整称量记录，推送给复核人移动端。
7. 复核人复核后电子签名，所有记录写入 SQLRustGo 不可变链。

**这个场景可以证明整个技术架构的可行性，而且不依赖其他系统。**

---

### 第三步：从"称量"逐步外扩

当称量场景稳定后，知识模型和 Agent 技能是可复用的。扩展路径：

- 称量 → 投料 → 混合 → 取样 → 检验 → 放行（完整 MES 批记录）
- 称量 → 物料接收 → WMS 入库检验
- 检验结果超限 → QMS 偏差自动化
- 设备校准到期 → 设备管理预警

## 八、当前阶段具体行动

### 立刻要做的两件事

1. **启动"GMP 知识抽取"专项**
   从已有的 2000 个文档中，挑出与选定产品/流程相关的核心文件（可能只有 10-20 份），使用 HermesAgent + 人工的方式，抽取出第一批规则和实体。这个工作可以并行进行，不依赖开发。

2. **搭建最小化技术栈**
   同时，开发团队搭建一个极简的端到端原型：
   - 一个可接收图片+语音的微信小程序（或 Flutter 页面）
   - 一个能调用 LLM（如 HermesAgent）进行 OCR/ASR 的接口
   - 一个规则匹配器（基于上一步产出的规则）
   - SQLRustGo 的写入接口（可以先用 Mock，或直接集成现有 API）

   **目标**：2 周内能将一张称量标签的照片，通过 Agent 变成一条可验证的 GMP 记录。

## 九、核心结论

在这个新的架构下，**先做 GMP 文档分析**不是可选，而是**唯一正确的起点**。

> 因为系统的"行为"不再由代码定义，而是由 GMP 知识定义。

原有的合规检索系统，就是从"查法规"开始的。现在需要将它进化成"可以自动执行的合规规则库"。

**现在最重要的事情就是分析已有的 GMP 文档和规范，并从中提炼出 Agent 能够用来执行任务的"数字知识"。**

有了这个基础，才能真正开始构建一个能听、能看、能判断、能推进流程的 GMP 智能体系统。
