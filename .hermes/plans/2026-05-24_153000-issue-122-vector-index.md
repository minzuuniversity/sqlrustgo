# SPEC: Issue #122 — 向量索引生成流水线

## 现状分析

- `gmp_embeddings` 表已有 **13898 条** embeddings（超过目标的 13809）
- FTS 检索正常（95.34%，389/408）
- 向量检索 **0/408 通过** — HNSW index 未被使用

**根因**：HNSW 索引在 StorageEngine 初始化时未从数据库恢复，导致 `search_vectors()` 始终返回空结果

## 目标

1. 使向量检索通道可工作（`search_vectors` → HNSW）
2. 向量 Recall@10 ≥ 0.80
3. 向量检索延迟 P95 < 50ms

## 验收标准

- [ ] `search_vectors` 返回非空结果（当前返回空）
- [ ] 向量模式通过率 > 0（当前 0/408）
- [ ] 向量 Recall@10 ≥ 0.80
- [ ] HNSW 索引持久化（重启后仍可用）

## 实施步骤

### Step 1: 诊断 HNSW 索引恢复流程

检查 `StorageEngine::new()` 中：

```
storage.rs line 227: migrate_embeddings() — 从 gmp_embeddings 表读取并写入 storage
storage.rs line 240: _ = storage.insert("gmp_embeddings", vec![record]) — 写入 sqlrustgo storage
storage.rs line 244: eprintln!("[migrate] Migrated {} embeddings", emb_count)
```

问题：`migrate_embeddings()` 将 embedding_json 写入 sqlrustgo storage，但 `hnsw_index.insert()` 仅在 `index_embeddings()` 时调用，初始化时没有构建 HNSW 索引。

### Step 2: 在 StorageEngine 初始化时重建 HNSW 索引

在 `StorageEngine::new()` 或 `migrate_embeddings()` 完成后，遍历 `gmp_embeddings` 表所有记录：

1. 读取 `chunk_id` + `embedding_json`
2. 反序列化 `Vec<f32>`
3. 调用 `hnsw_index.insert(chunk_id as u64, &embedding)`
4. 调用 `hnsw_index.build_index()` 构建 HNSW 图

### Step 3: 验证

运行 `gmp-eval` 确认：
- `search_mode` 包含 `vector`
- `vector_passed > 0`
- `Recall@10` ≥ 0.80

## 文件变更

- `crates/gmp-storage/src/storage.rs` — migrate_embeddings() 或 new() 中增加 HNSW 索引构建逻辑
- `crates/gmp-storage/src/hnsw_vector_index.rs` — 确认 build_index() 可用

## 风险

- `embedding_dim` 应为 bge-m3 的 1024（检查 storage.rs line 352, 459）
- Ollama bge-m3 模型已确认可用（15 models in Ollama）
