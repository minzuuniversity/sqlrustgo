## 一、目标定义

### 最小闭环定义

```
操作工拍照/语音 → HermesAgent 理解 → 规则判定 → 审计固证 → 记录生成
```

**核心验证点**: 一张称量标签的照片，通过 Agent 变成一条可验证的 GMP 记录，全程符合四层 AI 隔离原则。

### 成功标准

| 标准 | 指标 |
|------|------|
| 正常流程通过率 | 10/10 场景全部通过 |
| 偏差触发准确率 | 偏差场景 100% 自动触发 |
| 隔离原则合规 | 无任何 L0 数据泄露到 L2 |
| ALCOA 证据完整性 | 每条记录 5/5 原则全部满足 |
| 端到端延迟 | < 30 秒（从拍照到记录生成） |

## 二、系统架构（四层隔离）

```
┌─────────────────────────────────────────────────────────┐
│  移动端（微信小程序/Flutter）                              │
│  拍照/语音/扫码/电子签名                                   │
└───────────────────────┬─────────────────────────────────┘
                        │ HTTPS + JWT
                        ▼
┌─────────────────────────────────────────────────────────┐
│  L2 Cloud Zone: HermesAgent 编排层                        │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐                │
│  │ OCR/ASR  │ │ DSL 生成  │ │ Prompt   │                │
│  │ 多模态理解│ │ (仅抽象)  │ │ Firewall │                │
│  └──────────┘ └──────────┘ └──────────┘                │
└───────────────────────┬─────────────────────────────────┘
                        │ DSL (仅抽象指令)
                        ▼
┌─────────────────────────────────────────────────────────┐
│  L3 Validation Zone: 本地验证器                           │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐                │
│  │ DSL 验证  │ │ 权限检查  │ │ 审计验证  │                │
│  └──────────┘ └──────────┘ └──────────┘                │
└───────────────────────┬─────────────────────────────────┘
                        │ 验证通过的指令
                        ▼
┌─────────────────────────────────────────────────────────┐
│  L0 Trust Zone: 可信执行层                                │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐                │
│  │ 规则引擎  │ │ 证据组装  │ │ SQLRustGo│                │
│  │ (YAML)   │ │ (ALCOA)  │ │ 审计链    │                │
│  └──────────┘ └──────────┘ └──────────┘                │
│  ┌──────────┐ ┌──────────┐                             │
│  │ 实体库    │ │ 模拟数据  │                             │
│  │ (L0 only)│ │ (L0 only)│                             │
│  └──────────┘ └──────────┘                             │
└─────────────────────────────────────────────────────────┘
```

## 三、开发阶段

### Phase 0: 知识资产准备（1 周）

**目标**: 将 gmp_kg_build + gmp-qa-package 的文档资产按隔离层级整理到 agent-knowledge 目录

| 任务 | 产出 | 隔离层 |
|------|------|--------|
| 提取物料/设备/人员实体定义 | entities/*.yaml | L0 |
| 提取称量操作判定规则 | rules/weighing-rules.yaml | L0 |
| 提取偏差/CAPA 判定规则 | rules/deviation-capa-rules.yaml | L0 |
| 定义称量操作工作流 | workflows/weighing-workflow.yaml | L0 |
| 生成脱敏数据库 Schema | schemas/gmp-schema.sql | L1 |
| 生成合成模拟数据 | mock-data/weighing-mock-data.json | L1 |
| 定义 Agent DSL 模板 | dsl-templates/agent-dsl.yaml | L2 |
| 编写 Agent Prompt 模板 | agent-prompts/hermes-prompts.md | L2 |
| 定义本地验证器规则 | validators/local-validators.yaml | L3 |
| 定义测试场景 | test-scenarios/weighing-test-scenarios.yaml | L3 |

**当前状态**: 已完成（本目录即为产出）

### Phase 1: 规则引擎 + 本地验证器（2 周）

**目标**: 实现 L0 规则引擎和 L3 验证器，不依赖云模型

| 任务 | 技术方案 | 验收标准 |
|------|----------|----------|
| YAML 规则解析器 | Rust/Python，加载 weighing-rules.yaml | 能解析所有 7 条称量规则 |
| 实体查询接口 | PostgreSQL/SQLite，基于 agent-knowledge/L0 实体 | 能查询物料/设备/人员信息 |
| DSL 验证器 | Rust/Python，加载 local-validators.yaml | 能验证 DSL 格式和安全性 |
| 称量值范围判定 | 规则引擎，WEI-002 | 超限自动标记 |
| 偏差自动触发 | 规则引擎，WEI-007 + DEV-001 | 违规自动创建偏差 |
| ALCOA 证据组装 | 证据链生成器 | 每条记录包含完整证据链 |
| SQLRustGo 写入 | 审计链 API | 记录写入不可变链 |

**关键约束**:
- 此阶段所有代码在 L0 运行，仅使用本地 LLM
- 不调用任何云模型 API
- 规则引擎是确定性的（deterministic），不依赖 AI 推理

### Phase 2: Agent 编排层（2 周）

**目标**: 实现 L2 Agent 编排层，连接移动端和规则引擎

| 任务 | 技术方案 | 验收标准 |
|------|----------|----------|
| OCR 模块 | 本地 PaddleOCR 或云 API（仅传图片，不传上下文） | 能提取物料标签信息 |
| ASR 模块 | 本地 Whisper 或云 API（仅传音频，不传上下文） | 能提取称量值 |
| Prompt Firewall | 正则 + 规则检查 | 拦截所有敏感信息 |
| DSL 生成器 | 本地 LLM（Qwen3/DeepSeek） | 生成合规 DSL |
| Data Diode | 单向数据网关 | L0 数据不泄露到 L2 |
| Token 替换器 | 实体替换引擎 | 真实值→占位符 |

**关键约束**:
- 云模型只接收脱敏数据（L1 层 Schema + Mock）
- 云模型只输出 DSL（不直接操作数据）
- Prompt Firewall 必须在云调用前拦截

### Phase 3: 移动端 + 端到端集成（2 周）

**目标**: 实现移动端采集和端到端闭环

| 任务 | 技术方案 | 验收标准 |
|------|----------|----------|
| 微信小程序/Flutter 页面 | 拍照/语音/扫码 UI | 操作工可完成称量操作 |
| JWT 认证 | 操作工身份验证 | 支持扫码/人脸识别 |
| 电子签名 | 移动端签名组件 | 复核人可签名确认 |
| 端到端测试 | 10 个测试场景 | 全部通过 |
| 性能测试 | 延迟测量 | 端到端 < 30 秒 |

### Phase 4: 验证与文档（1 周）

**目标**: 完成合规验证和文档输出

| 任务 | 产出 |
|------|------|
| 10 个测试场景执行 | 测试报告 |
| 隔离合规审计 | 审计报告（证明无 L0 数据泄露） |
| ALCOA 证据完整性验证 | 证据链检查报告 |
| 用户验收测试 | UAT 报告 |
| 系统文档 | 安装部署指南 |

### 4.2 隔离合规验证

| 验证项 | 方法 | 通过标准 |
|--------|------|----------|
| L0 数据不出云 | 网络流量监控 | 无 L0 数据出现在 L2/L3 的网络请求中 |
| Prompt 无敏感信息 | Prompt Firewall 日志 | 所有 Prompt 经过脱敏，无真实批号/物料名/参数值 |
| 云模型仅输出 DSL | 输出格式验证 | 云模型输出 100% 为 DSL 格式，无直接数据操作 |
| 本地验证器拦截 | 注入测试 | 所有恶意输入被验证器拦截 |
| 审计链完整 | SQLRustGo 查询 | 所有操作有审计记录，不可篡改 |

### 4.3 性能验证

| 指标 | 目标 | 测量方法 |
|------|------|----------|
| OCR 提取延迟 | < 3 秒 | 从拍照到提取结果 |
| ASR 提取延迟 | < 2 秒 | 从语音到文字 |
| 规则判定延迟 | < 1 秒 | 从输入到判定结果 |
| 审计链写入延迟 | < 2 秒 | 从记录生成到写入确认 |
| 端到端延迟 | < 30 秒 | 从拍照到记录生成完成 |

## 五、技术栈

| 组件 | 技术选型 | 隔离层 |
|------|----------|--------|
| 规则引擎 | Rust (基于 SQLRustGo GMP Crate) | L0 |
| 实体数据库 | PostgreSQL / SQLite | L0 |
| 审计链 | SQLRustGo | L0 |
| 本地 LLM | Qwen3-8B / DeepSeek-7B (Ollama) | L0/L2 |
| OCR | PaddleOCR (本地) 或 MiniMax API (脱敏) | L2 |
| ASR | Whisper (本地) 或 MiniMax API (脱敏) | L2 |
| Prompt Firewall | Rust/Python 正则引擎 | L2 |
| DSL 验证器 | Rust | L3 |
| 移动端 | 微信小程序 / Flutter | Client |
| 认证 | JWT + 生物识别 | Client |

## 六、风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|----------------|
| 本地 LLM 推理能力不足 | DSL 生成质量差 | 先用规则引擎兜底，LLM 仅辅助 |
| OCR/ASR 准确率不够 | 物料/称量信息提取错误 | 人工确认环节 + 置信度阈值 |
| 云 API 调用泄露 L0 数据 | 合规风险 | Prompt Firewall + Data Diode 双重保护 |
| 规则引擎覆盖不全 | 漏判偏差 | 从 knowledge_base_docs 精炼文档补充规则 |
| 移动端体验差 | 操作工不愿使用 | 极简化设计，最少点击次数 |
